## 3. Висновки

1. **Властивості моделі vs Обв'язка**:
   - Спочатку тестувалася модель `qwen2.5-coder:1.5b`. Через замалий розмір (1.5B) вона не витримувала багатоходовий виклик інструментів у Messages-формі: зациклювалася на помилці схеми Zod, повертала текстові розмірковування замість блоків виклику або генерувала порожній масив `files: []`.
   - Додавання суворої валідації `.min(1)` у `ProposalSchema`, покращення підказок у разі помилки валідації та перехід на модель `qwen2.5-coder:7b` забезпечили стабільний результат **10 з 10**.
2. **Пастка рекурсивного дослідження та ліміти хмари (HTTP 429)**:
   - Під час першого прогону `gemini` модель пішла ланцюжком рекурсивного виклику `list_files` по всіх директоріях (6 кроків поспіль), що миттєво призвело до перевищення ліміту частоти запитів Gemini Free Tier (`HTTP 429: Too Many Requests`). Механізм експоненційного retry в адаптері та лаконічний системний промпт дозволили втримати модель у межах 2 кроків без перевищення квот.
3. **Безпека та межі автономності**:
   - Функція `resolveInside` жорстко обмежує агента коренем репозиторію та блокує доступ до конфігураційних файлів із секретами (`.env*`).
   - На рівні автономності **L1** агент має право лише читати файли (`list_files`, `read_file`), а фінальне рішення повертає оператору у вигляді структурованого JSON для ручного аудиту перед збереженням у репозиторій.

## 4. Власний цикл vs AI SDK 7

| Що | Власний цикл (крок 08) | AI SDK 7 (крок 09) |
|---|---|---|
| **Рядків коду разом з інструментами** | **259 рядків** (`agent-loop.ts` + `tools.ts`) | **105 рядків** (`agent-aisdk.ts`) |
| **Історія повідомлень, розбір викликів інструментів, повтор** | Рукописний цикл у `runAgentLoop`: масив `messages`, обробка викликів, стикування чергування ролей (~45 рядків) | Декларативний `ToolLoopAgent` та виклик `agent.generate()` (автоматично фреймворком) |
| **Ліміт кроків** | Власний лічильник `for (let step = 1; step <= o.maxSteps; step++)` | Декларативна умова `stopWhen: isStepCount(maxSteps)` |
| **Бюджет токенів** | Власна умова зупинки `usage.inputTokens + usage.outputTokens >= o.tokenBudget` | Відсутній із коробки (потрібно підсумовувати вручну через `step.usage`) |
| **Облік токенів** | Власні функції `fromMessagesUsage`, `fromChatUsage` та сума `addUsage` | Вбудований у SDK: загальний `result.usage` та окремо за кожним кроком `step.usage` |
| **Валідація структурованого виходу** | Власний `extractJson` + `schema.safeParse` + відправка помилки назад моделі | Декларативний `output: Output.object({ schema })` |
| **Підтвердження деструктивної дії** | Не реалізовано (інструменти були лише read-only) | Вбудована «драбина довіри»: `toolApproval: { write_file: 'user-approval' }` та двоетапний `generate` |
| **Друга форма API або провайдер** | Окремі написані вручну адаптери `createMessagesAdapter` та `createChatAdapter` | Зміна одного виклику в `pickModel()` (`google(...)`, `createOllama(...)`, `createOpenAICompatible(...)`) |

* **З'явилося**: Вбудований механізм «драбини довіри» (`toolApproval`), що блокує виконання деструктивних операцій на рівні SDK до прямого схвалення користувачем.
