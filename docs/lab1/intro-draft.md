# Вступна частина звіту (Intro Draft) — Лабораторна 1 (Крок 11)

## 1. Проблема та актуальність
Сучасна агентна інженерія (Agentic Engineering) вимагає переходу від неструктурованого спілкування з LLM до детермінованих циклів з чіткими межами автономності. Відсутність жорстких обмежень призводить до нескінченних викликів інструментів, вичерпання бюджетів і ризиків витоку конфіденційних даних (`.env`).

## 2. Мета роботи
Проектування, реалізація та експериментальне дослідження детермінованого агентного циклу (`runAgentLoop`) з нульовою залежністю від сторонніх SDK, з контролем витрат токенів, лімітом кроків та суворою контрактною валідацією.

## 3. Ключові інваріанти архітектури
1. **Інваріантне ядро**: функція `runAgentLoop` оперує нейтральними структурами повідомлень (`Message`, `ToolCall`, `ToolResult`) і не знає про специфіку конкретних API.
2. **Дві форми API через адаптери**:
   - `createMessagesAdapter`: Messages-форма (Anthropic, Ollama `/v1/messages`).
   - `createChatAdapter`: Chat Completions-форма (OpenAI, Gemini, OpenRouter).
3. **Межі безпеки (Sandbox Guardrails)**:
   - Інструменти `list_files` та `read_file` обмежені межами кореня проєкту.
   - Спроби зчитування секретів (`.env*`) суворо відхиляються на рівні `resolveInside` зі статусом `denied`.
4. **Валідація виходів**: результат роботи зараховується тільки після проходження Zod-схеми з прапорцем `.strict()`.

## 4. Підсумок результатів
- Реалізовано та верифіковано маршрут `GET /api/health` трьома виконавцями (агент кодування, власний хмарний цикл, власний локальний цикл).
- Доведено стійкість ядра зупинками без мережевих викликів (`token-budget`, `max-steps`).
- Забезпечено 10 з 10 валідних структурованих виходів у локальному середовищі.
