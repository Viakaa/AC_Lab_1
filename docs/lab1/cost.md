## 2. Кешування промпту (пара викликів: перший / другий)

- **Провайдер / Модель**: Ollama / `qwen3:4b` (або `qwen2.5-coder:7b`)
- **Версія Ollama**: `0.40.3`
- **Дата вимірювання**: `2026-10-12`
- **Принцип дії**: у локальній моделі це повторне використання KV-кешу префікса в оперативній пам'яті (prefix caching). При повторному запиті з тим самим системним контекстом токени зчитуються з пам'яті миттєво.

### Перший виклик (Cold Cache — холодний старт):
```json
{
  "prompt_tokens": 995,
  "prompt_tokens_details": {
    "cached_tokens": 0
  },
  "completion_tokens": 1994,
  "total_tokens": 2989
}
```

### Другий виклик (Hot Cache — гарячий кеш):
```json
{
  "prompt_tokens": 995,
  "prompt_tokens_details": {
    "cached_tokens": 975
  },
  "completion_tokens": 1994,
  "total_tokens": 2989
}
```
*Результат*: 975 токенів із 995 (98%) зчитано з кешу префікса без повторного обчислення.

### 1. Що було неправильно в таблиці «Три прогони»

- **«$ за прайсом» пораховано не за тими цінами.** Функція `getSpec` у `scripts/measure-loop.ts` шукала модель умовою
  `m.id.includes('gemini')`, тож для **кожного** прогону поверталась перша gemini-модель каталогу — `gemini-3.5-flash-lite` (0.3 / 2.5).
  Перевірка: (1022 × 0.3 + 155 × 2.5) / 10⁶ = 0.000694 — рівно число з таблиці; так само 0.008740 і 0.001200.
  Виправлено: `getSpec` шукає лише точний збіг id, а моделі поза каталогом (шлюз `:free`, Ollama) мають ціну 0.
- **Затримки округлені.** Скрипт друкував час у секундах (`Math.round(latencyMs / 1000)`), тому 46000 і 80000 мс — це «46 с» і «80 с».
  Виправлено: скрипт тепер друкує мс і готовий рядок таблиці через `costTableRow` з `src/cost.ts`.
- **Оцінка 1020 у рядку хмари не виміряна для цього прогону.** `scripts/measure-loop.ts` оцінку до виклику не рахує. Число 1020 перейшло
  з попереднього рядка (`gemini-2.5-flash`, факт 1017, коміт `f04ba6c`). Нижче в рядку хмари стоїть «—», а звірку оцінки наведено окремо в розділі 3.

### 4. Кешування — модель

Пару викликів «перший / другий» у розділі «Кешування промпту» виміряно на **`qwen3:4b`** (Ollama, 2026-10-12).
У першій версії файлу (коміт `1e22386`) є рядок `ollama | qwen3:4b | 995 | 975 | 1994 | … | 197647 | 2026-10-12`. Його числа (995 вхідних,
975 кешованих, 1994 вихідних) збігаються з парою викликів. Приписка «(або `qwen2.5-coder:7b`)» — неточність пізнішого коміту.
Назва поля кешу: `prompt_tokens_details.cached_tokens` (OpenAI-сумісна відповідь Ollama). Це повторне використання префікса, а не знижка в рахунку.
