# Специфікація MCP-сервера

- Назва сервера й версія: lab2-corpus / 1.0.0
- Транспорт: stdio (локальний процес, запускає клієнт)
- Ревізія протоколу: 2026-07-28 (`@modelcontextprotocol/server` 2.x)
- Команда запуску: `npx tsx src/mcp/server.ts` (`npm run mcp`)
- Що сервер читає: `data/index.json` (закомічений індекс кроку 04 — у ньому й тексти фрагментів)
- Куди звертається: лише до локальної Ollama (`OLLAMA_BASE_URL`, типово `http://127.0.0.1:11434`) — ембедити запит `search_corpus` тією самою моделлю `embeddinggemma-2:270m`, що будувала індекс
- Що сервер пише: один рядок на виклик у `docs/lab2/traces/mcp-calls.jsonl` (інструмент, аргументи, результат, `source` — хто викликав); більше нічого
- Чого сервер не робить ніколи: не читає й не змінює нічого поза індексом, не приймає шлях від клієнта, не звертається в мережу, крім ембедера запиту, не виконує команд
- Секрети: не потрібні — індекс закомічений, Ollama локальна й без ключа; у конфігурації підключення ключів немає

## Інструмент 1 — search_corpus
- Призначення: гібридний пошук (вектор + BM25, RRF, крок 05) по колекції, повертає фрагменти з цитатами
- Вхід: `query: string` (1..500 символів), `topK: integer` (1..10, типово 5); інших полів немає (`.strict()`)
- Вихід: до `topK` блоків тексту; у кожному — `[chunkId] docId › heading · символи start–end`, `cosine`, `rrf` і текст фрагмента
- Межі: `topK` > 10 і запит > 500 символів відхиляються схемою, а не обрізаються; текст фрагмента — не довше за 1200 символів (це й так максимум фрагмента за правилом кроку 04)
- Правила безпеки: шляхів на вхід не приймає; таймаут обробника 10 с (коротший за таймаути клієнтів — 60 с у Codex CLI, 600 с у Gemini CLI); в описі інструмента сказано, що текст фрагментів — дані з документів, а не інструкції
- Хто може викликати: локальний агент кодування і мій застосунок (крок 09) на цій машині; інших викликачів немає — транспорт stdio, процес породжує сам клієнт

## Інструмент 2 — fetch_chunk
- Призначення: віддати один фрагмент за id
- Вхід: `id: string` за шаблоном `^doc-\d{2}#\d{4}$` (наприклад `doc-13#0001`); інших полів немає (`.strict()`)
- Вихід: один блок тексту з тими самими полями, що й у `search_corpus` (без `cosine`/`rrf`)
- Межі: приймаються лише id, які Є в завантаженому індексі (allowlist — сам індекс, 556 фрагментів); усе інше — відмова з причиною (`isError: true`), а не порожній результат
- Правила безпеки: `../../.env`, абсолютний шлях, injection у id не проходять навіть схему — параметра-шляху в інструмента немає; мережі не потребує (нічого не ембедить)
- Хто може викликати: те саме, що в інструменті 1

## Сценарії зловживання і тести, які їх ловлять
| Зловживання | Очікувана поведінка | Тест |
|---|---|---|
| `id = ../../.env` | відхилено схемою, файл не читається | `tests/mcp.test.ts` · «відмова: вийти за межі індексу не вдається» |
| `id = C:\Users\…\.ssh\id_rsa` | відхилено схемою | тут само |
| `id = doc-99#0000` (формат правильний, такого фрагмента немає) | відмова з причиною «немає в індексі» | тут само |
| `topK = 10000` | відхилено схемою | `tests/mcp.test.ts` · «порушення схеми» |
| `query = ""` або понад 500 символів | відхилено схемою | тут само |
| зайве поле у вході (`{ query, path }`) | відхилено схемою (`.strict()`) | тут само |
| ембедер завис | відмова «перевищено таймаут 10000 мс» | `withTimeout` у `src/mcp/tools.ts` |
| інструкція всередині тексту фрагмента | повертається як дані; опис інструмента прямо каже не виконувати | — (захист у клієнті, крок 09) |
